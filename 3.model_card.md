## Model Description

### Input

Each query is a hyphen-separated vector of real-valued inputs, one per function dimension, all constrained to $[0, 1]$:

| Function | Dimensions | Example input format |
|----------|------------|----------------------|
| F1 | 2D | `0.703500-0.716000` |
| F2 | 2D | `0.701523-0.379257` |
| F3 | 3D | `0.000000-1.000000-0.425707` |
| F4 | 4D | `0.397377-0.367719-0.385939-0.387398` |
| F5 | 4D | `0.995000-0.995000-0.995000-0.995000` |
| F6 | 5D | `0.442035-0.373720-0.624334-0.734770-0.090751` |
| F7 | 6D | `0.174678-0.000000-0.504524-0.280666-0.306003-0.661563` |
| F8 | 8D | `0.230253-0.140670-0.139764-0.348554-0.941978-0.540687-0.073606-0.516202` |

The pipeline reads all historical inputs from `week{n}_inputs.txt` files and the initial dataset from `.npy` files. The version parameter `WEEK_NO` controls which historical data is loaded.

### Output

For each function, the pipeline outputs a single proposed query point — the input vector predicted to maximise the unknown function's output. The pipeline also returns:

- **Posterior mean** $\mu(x^*)$ at the proposed point
- **Posterior standard deviation** $\sigma(x^*)$ at the proposed point
- **Acquisition function value** at the proposed point
- **Diagnostic plots** (GP posterior surface, acquisition function, parallel coordinates for $N > 3$)

### Model Architecture

The pipeline is a **Sequential Model-Based Optimisation (SMBO)** system built on BoTorch and GPyTorch. It comprises three components:

**1. Gaussian Process Surrogate**

A `SingleTaskGP` with:
- Matérn kernel (ARD-enabled, per-function smoothness parameter $\nu$)
- `ScaleKernel` wrapper (learns output variance $\sigma_f^2$)
- `Standardize` outcome transform (zero-mean normalisation)
- Per-function noise floor constraint

**2. Acquisition Function (per-function, final configuration)**

| Function | Acquisition | Rationale |
|----------|-------------|-----------|
| F1 | Localised EI | GP bypassed for sharp peak; search constrained to $x_1 \in [0.694, 0.714]$, $x_2 \in [0.706, 0.726]$ |
| F2 | UCB ($\kappa=0.8$) | Exploit confirmed best at $(0.697, 0.321)$ |
| F3 | UCB ($\kappa=2.0$) | Moderate exploration; smooth 3D landscape |
| F4 | EI | Exploit W11 breakthrough at $(0.418, 0.384, 0.407, 0.350)$ |
| F5 | Manual override | Boundary corner $(1,1,1,1)$ confirmed optimum; override probes neighbourhood |
| F6 | EI | Exploit confirmed best; TS replaced after 3 regressions |
| F7 | EI | Consistent improvement trajectory; unchanged throughout |
| F8 | TuRBO + Thompson Sampling | Trust-region BO for 8D; global GP unreliable at this dimensionality |

**3. Acquisition Optimiser**

- **F1, F2, F3, F4, F6, F7:** `optimize_acqf` with 512 raw samples and 32 gradient-based restarts
- **F5:** Hard-coded override (EI cannot propose beyond $[0,1]^4$ boundary)
- **F8:** `MaxPosteriorSampling` over 2048 candidates within anisotropic trust region

**Per-function kernel configuration:**

| Function | $\nu$ | Length-scale bounds | Noise constraint |
|----------|--------|---------------------|-----------------|
| F1 | 1.5 | (0.005, 0.05) — very tight | $(10^{-6}, 10^{-3})$ — tight |
| F2 | 1.5 | (0.05, 0.5) | $(10^{-5}, 10^{-1})$ |
| F3 | 2.5 | (0.1, 1.0) | $(10^{-5}, 10^{-1})$ |
| F4 | 1.5 | (0.05, 0.5) | $(10^{-5}, 10^{-2})$ — tight |
| F5 | 2.5 | (0.1, 1.5) — wide | $(10^{-5}, 10^{-1})$ |
| F6 | 2.5 | (0.05, 0.75) | $(10^{-5}, 10^{-1})$ |
| F7 | 2.5 | (0.05, 1.0) | $(10^{-5}, 10^{-1})$ |
| F8 | 2.5 | (0.05, 1.0) | $(10^{-5}, 10^{-1})$ |

## Limitations

### 1. GP Smoothness Assumption Violated by F1

The Matérn kernel assumes at least once-differentiable functions. F1's near-singular peak — outputs spanning $10^{-124}$ to $10^{-9}$ across a tiny input region — violates this assumption severely. Every acquisition function tested (MES, EI, localised EI) failed to match the W2 manual best of $1.81 \times 10^{-9}$, set before the GP was introduced. The GP fits a gentle hill over a needle-like spike, systematically misrepresenting the function's structure.

### 2. F3 — Unbeaten Initial Data Point

The original dataset's best point $(0.492581, 0.611593, 0.340176)$ with output $-0.034835$ was never improved upon across all 13 rounds. The GP consistently identified boundary regions as promising when the true optimum was an interior point. This represents a fundamental failure of the smooth surrogate on a function with complex interior structure.

### 3. Stationarity Assumption

The Matérn kernel assumes constant length-scales across the input space. For F4 (dynamic warehouse system) and F8 (8D hyperparameter tuning), the function may be rough in some regions and smooth in others. Non-stationary kernels or input warping would address this but are not implemented.

### 4. Small Dataset Regime

With 10–47 data points per function, the GP posterior has high variance in unexplored regions. Thompson Sampling draws sample paths that occasionally peak in genuinely poor areas — observed as three consecutive regressions for F6 (W9–W11). This failure mode is inherent to small-dataset BO and cannot be fully resolved without more evaluations.

### 5. Boundary Constraint

EI cannot propose points beyond the $[0,1]^N$ boundary. For F5, whose true optimum is at the boundary corner $(1,1,1,1)$, this required a manual override mechanism. Functions with optima at or near boundaries require special handling not provided by standard acquisition function optimisers.

### 6. Computational Scaling

- GP fitting: $O(n^3)$ — negligible at current scale ($n \leq 50$) but limiting beyond ~500 points
- `optimize_acqf`: 512 raw samples × 32 restarts — reliable for $\leq 6$D; potentially insufficient for 8D (addressed by TuRBO)
- Thompson Sampling: stochastic — results vary across runs unless `torch.manual_seed()` is fixed

## Trade-offs

### 1. Exploration vs Exploitation

The most consequential trade-off in the capstone. Setting UCB $\kappa=1000$ for F5 (extreme exploration) discovered the boundary optimum yielding 8662 — a result impossible through conservative exploitation. The same extreme exploration setting for F1 (MES) produced $8.80 \times 10^{-83}$ — catastrophic failure. The trade-off is not resolvable in advance without knowledge of the function's structure; it must be calibrated empirically from observed outputs.

| Setting | Risk | Reward | Best for |
|---------|------|--------|----------|
| High $\kappa$ / MES | Wasted queries on poor regions | Discovers unknown optima | Unknown landscapes, early rounds |
| Low $\kappa$ / EI | Local optima trap | Reliable convergence | Confirmed smooth functions, late rounds |
| Thompson Sampling | Stochastic regression | Escapes deterministic traps | Multi-modal functions with sufficient data |
| TuRBO | Misses global optima outside TR | Reliable high-D convergence | High-dimensional functions ($N \geq 6$) |

### 2. Surrogate Flexibility vs Computational Cost

More flexible surrogates (deep GPs, Bayesian neural networks) would better model F1's sharp peak and F3's complex interior structure. However, at 10–50 data points, these models overfit severely and provide unreliable uncertainty estimates. The Matérn GP is the correct choice at this scale — the trade-off is accepting systematic misspecification on structurally unusual functions.

### 3. Global vs Local Optimisation

Standard BO with `optimize_acqf` optimises the acquisition function globally — appropriate for low-dimensional functions (F1–F7) but unreliable in 8D (F8) where the acquisition surface has exponentially many local maxima. TuRBO resolves this by restricting candidates to a trust region, trading global coverage for local reliability. The trade-off: TuRBO may miss a better global optimum outside the trust region, as observed when F8's TR contracted around a suboptimal centre in W10.

### 4. Automation vs Manual Intervention

The bespoke pipeline automates query proposal for F2–F4, F6–F8 but requires manual overrides for F1 (localised EI bounds) and F5 (boundary override). Full automation would require a meta-learning layer that detects surrogate misspecification and switches strategies — beyond the scope of the current implementation. The trade-off is between reproducibility (automated pipeline) and adaptability (manual intervention when the model fails).

### 5. Single Query Per Round Constraint

The one-query-per-function-per-module constraint is the binding limitation of the entire capstone. It prevents within-round correction, amplifies the cost of each wrong decision, and makes it impossible to validate whether an observed output is genuine or a noise spike. In a real deployment, the surrogate would be updated after every evaluation — the module cadence artificially inflates the cost of each miscalibration.
