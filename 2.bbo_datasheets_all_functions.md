# FUNCTION 1 DATASHEET

## Function Overview

1. **Function:** Function 1 — Contamination / Radiation Source Detection
2. **Real-world scenario:** Locating a contamination or radiation source in a 2D environment. The function simulates a sensor reading that peaks sharply at the true source location and falls to near-zero everywhere else.
3. **Dimensionality:** 2D (inputs: x₁, x₂)
4. **Initial data points:** 10 (array shape: 10 × 2)
5. **Output:** Scalar signal intensity — a proxy for proximity to the contamination source. Higher = closer to source.

## Nature of the Data

1. **Initial dataset structure:** Inputs: (10, 2) NumPy array; Outputs: (10,) NumPy array. Outputs ranged from ~10⁻¹²⁴ to ~10⁻¹⁶ — an extreme dynamic range spanning over 100 orders of magnitude.
2. **Dataset evolution:** One new point added per module (13 total weekly queries). Early queries used manual bisection; later queries used EI with tight length-scale bounds. Sampling progressively concentrated near (0.703, 0.716).
3. **Noise/randomness:** Function appears deterministic — repeated evaluations at the same point return identical outputs. No noise correction was applied.
4. **Function character:** Strongly unimodal with a near-singular peak. The GP posterior consistently underestimated the peak's sharpness, fitting a smooth hill over a needle-like spike. Output variation of 100+ orders of magnitude across the input space is the defining structural feature.

## Optimisation Strategy

1. **Methods used:** Manual bisection (W1–W4); GP with MES acquisition (W5–W9); GP with EI and tight length-scale bounds (W10–W12); Localised EI constrained to peak neighbourhood (W12–W13).
2. **Rationale:** The extreme dynamic range made standard GP fitting unreliable — the Matérn kernel's smoothness assumption was violated by the near-singular peak. MES was chosen for its information-theoretic properties but proved too exploratory. EI with tight length-scale bounds (0.005, 0.05) was the most effective configuration.
3. **Exploration–exploitation balance:** Near-pure exploitation throughout. The function's extreme sharpness means any exploratory query returns effectively zero output.
4. **Strategy changes:** MES → EI (W10) after MES produced 8.80×10⁻⁸³. Localised EI introduced (W12) to constrain the search to a small box around the known best, guaranteeing a new query without duplicating W2.

## Data Handling and Preprocessing

1. **Rescaling:** Inputs already in [0,1]. The `Standardize` outcome transform in BoTorch normalised outputs to zero mean — critical given the extreme output range.
2. **Surrogate model:** BoTorch `SingleTaskGP` with Matérn-1.5 ARD kernel.
3. **Preprocessing:** Matérn ν=1.5 (once-differentiable, appropriate for jagged function); length-scale bounds tightened to (0.005, 0.05); noise constraint (10⁻⁶, 10⁻³) to prevent noise absorption flattening the posterior.
4. **Outliers:** No outliers removed. Negative outputs (W10: −1.27×10⁻³²) were retained as genuine function evaluations.

## Weekly Iteration and Learning

1. **Landscape understanding:** The initial data revealed the extreme dynamic range immediately. Each new query confirmed that the function is essentially zero everywhere except in a tiny neighbourhood of (0.703, 0.716).
2. **Local optima:** Not applicable — function is unimodal. The challenge was locating the single peak, not avoiding local optima.
3. **Most informative queries:** W2 manual bisection at (0.703500, 0.716000) — produced the all-time best (1.81×10⁻⁹) and was never surpassed. W12 localised EI at (0.713500, 0.726000) — confirmed the peak neighbourhood but slightly overshot.
4. **If restarting:** Use EI with tight length-scale bounds from Module 12. Never use MES. Implement a localised search box around the best point from the third query onward.

## Performance and Results

1. **Best output:** 1.81×10⁻⁹
2. **Best input:** (0.703500, 0.716000) — achieved in Week 2 via manual bisection.
3. **Confidence in global maximum:** Moderate. The function is confirmed unimodal, and the best point has been approached from multiple directions without improvement. However, the GP's systematic failure to model the peak means the true maximum location cannot be precisely characterised.
4. **Alignment with expectations:** Partially. The contamination detection scenario correctly predicted a sharp, localised peak. The severity of the dynamic range (100+ orders of magnitude) was not anticipated and caused systematic surrogate failure.

## Ethical, Practical and General Considerations

1. **Real-world relevance:** Radiation source localisation, environmental contamination mapping, signal source detection in communications.
2. **Synthetic limitations:** The true source location and signal model are unknown. In a real deployment, domain knowledge (e.g., physical decay models) would constrain the search space and inform the kernel choice.
3. **Scalability:** The localised EI approach scales well. For higher-dimensional contamination problems, TuRBO would be the natural extension.
4. **Risks for future users:** The extreme dynamic range will cause numerical issues in standard GP implementations without log-transformation or output standardisation. MES should be avoided for near-singular functions.

# FUNCTION 2 DATASHEET

## Function Overview

1. **Function:** Function 2 — Noisy Log-Likelihood Optimisation
2. **Real-world scenario:** A black-box ML model returning a log-likelihood score. The function is noisy and potentially multi-modal, simulating hyperparameter tuning of a probabilistic model.
3. **Dimensionality:** 2D (inputs: x₁, x₂)
4. **Initial data points:** 10 (array shape: 10 × 2)
5. **Output:** Log-likelihood score. Higher = better model fit.

## Nature of the Data

1. **Initial dataset structure:** Inputs: (10, 2); Outputs: (10,). Initial outputs ranged from −0.066 to +0.611 — moderate, human-readable values.
2. **Dataset evolution:** 13 weekly queries added. Early queries explored the upper-x₂ boundary; later queries converged toward (0.70, 0.38) after UCB κ reduction.
3. **Noise/randomness:** Described as noisy in the function specification. Outputs varied slightly between near-identical queries, suggesting stochastic evaluation.
4. **Function character:** Likely multi-modal with moderate noise. The GP posterior showed multiple local peaks, and different acquisition strategies produced very different query locations.

## Optimisation Strategy

1. **Methods used:** Manual weighted interpolation (W1–W4); GP/UCB κ=3.0 (W5–W8); GP/UCB κ=1.0 (W9–W11); GP/UCB κ=0.8 (W12–W13).
2. **Rationale:** UCB was appropriate given the noisy, potentially multi-modal landscape. Progressive κ reduction reflected increasing confidence in the identified best region around (0.70, 0.38).
3. **Exploration–exploitation balance:** Started balanced (κ=3.0), shifted toward exploitation (κ=0.8) as the best region was confirmed. W9's κ=3.0 query to (0.957, 0.997) returning 0.057 demonstrated the cost of over-exploration.
4. **Strategy changes:** κ reduced from 3.0 → 1.0 → 0.8 across three amendments, each driven by observed over-exploration failures.

## Data Handling and Preprocessing

1. **Rescaling:** Inputs in [0,1]. `Standardize` transform applied.
2. **Surrogate model:** BoTorch `SingleTaskGP` with Matérn-1.5 ARD kernel.
3. **Preprocessing:** ν=1.5 for moderate sharpness; length-scale bounds (0.05, 0.5); noise constraint (10⁻⁵, 10⁻¹).
4. **Outliers:** No outliers removed. The W9 output of 0.057 (from a poor exploratory query) was retained and informed the κ reduction decision.

## Weekly Iteration and Learning

1. **Landscape understanding:** The initial data suggested a peak near (0.70, 0.93). Subsequent queries revealed the true optimum was lower in x₂ — around (0.70, 0.38) — a region not well-represented in the initial data.
2. **Local optima:** Likely present. The function description warns of multiple local peaks, and the initial best at (0.703, 0.927) was eventually surpassed by a completely different region.
3. **Most informative queries:** W11 at (0.697, 0.321) → 0.692; W13 at (0.702, 0.379) → 0.814. These confirmed the low-x₂ region as genuinely superior to the initial best.
4. **If restarting:** Begin with moderate κ=1.5 and reduce progressively. Explore the full x₂ range more systematically in early rounds.

## Performance and Results

1. **Best output:** 0.8135
2. **Best input:** (0.701523, 0.379257) — achieved in Week 13 (final round).
3. **Confidence in global maximum:** Moderate. The final query produced the best output, suggesting the optimum may lie further in the same direction.
4. **Alignment with expectations:** Partially. The multi-modal warning was accurate — the true optimum was in a completely different region from the initial best.

## Ethical, Practical and General Considerations

1. **Real-world relevance:** Probabilistic model selection, Bayesian inference hyperparameter tuning, variational autoencoder optimisation.
2. **Synthetic limitations:** Real log-likelihood surfaces are typically higher-dimensional and may have sharper gradients near the true optimum.
3. **Scalability:** UCB with progressive κ reduction is a standard, scalable approach. For higher-dimensional versions, ARD length-scales would identify which input dimensions drive the log-likelihood most strongly.
4. **Risks:** Over-exploitation of the initial best region. The W1–W4 manual strategy anchored too strongly to (0.703, 0.927), delaying discovery of the true optimum by several rounds.

# FUNCTION 3 DATASHEET

## Function Overview

1. **Function:** Function 3 — Drug Side Effect Minimisation
2. **Real-world scenario:** Drug discovery — testing combinations of three compounds to minimise adverse reactions. The output is the negated adverse reaction count (higher = fewer side effects = better).
3. **Dimensionality:** 3D (inputs: x₁, x₂, x₃ representing compound amounts)
4. **Initial data points:** 15 (array shape: 15 × 3)
5. **Output:** Negated adverse reaction severity. All outputs negative by design — maximising means minimising side effects.

## Nature of the Data

1. **Initial dataset structure:** Inputs: (15, 3); Outputs: (15,). All outputs negative, ranging from −0.399 to −0.035.
2. **Dataset evolution:** 13 weekly queries added. The GP repeatedly proposed boundary points (x₂≈1.0 or x₂≈0.0), none of which improved on the initial best interior point.
3. **Noise/randomness:** Function appears deterministic. No evidence of stochastic evaluation.
4. **Function character:** Unclear — the smooth GP surrogate consistently failed to identify the true optimum. The interior best (−0.035) was never beaten by any boundary query, suggesting complex interior structure that the Matérn-2.5 kernel could not capture.

## Optimisation Strategy

1. **Methods used:** Manual weighted interpolation with x₃ suppression (W1–W4); GP/UCB κ=2.0 (W5–W13). Strategy largely unchanged due to persistent failure to improve.
2. **Rationale:** UCB with moderate κ was chosen for the 3D smooth landscape. However, the GP's boundary attraction — proposing x₂≈0 or x₂≈1 repeatedly — suggests the surrogate was misspecified.
3. **Exploration–exploitation balance:** Moderate throughout. The GP consistently identified boundary regions as high-uncertainty, directing queries there despite poor historical performance.
4. **Strategy changes:** Minimal. The persistent failure of all strategies to beat the initial best suggests a fundamental model mismatch rather than a tunable parameter issue.

## Data Handling and Preprocessing

1. **Rescaling:** Inputs in [0,1]. `Standardize` transform applied to negative outputs.
2. **Surrogate model:** BoTorch `SingleTaskGP` with Matérn-2.5 ARD kernel.
3. **Preprocessing:** ν=2.5 (smooth function assumed); length-scale bounds (0.1, 1.0); noise constraint (10⁻⁵, 10⁻¹).
4. **Outliers:** No outliers. The worst point (−0.399, Point 7 with x₃=0.991) confirmed high x₃ causes severe adverse reactions.

## Weekly Iteration and Learning

1. **Landscape understanding:** Initial data clearly showed x₃ as the most harmful dimension at high values. However, the GP failed to exploit this signal, instead being attracted to boundary regions.
2. **Local optima:** Possibly present. The interior best at (0.493, 0.612, 0.340) may be a local optimum, with the global optimum elsewhere — but the GP never found it.
3. **Most informative queries:** The original data Point 4 (0.493, 0.612, 0.340) → −0.035. This was the most informative point in the entire dataset and was never surpassed.
4. **If restarting:** Use a non-stationary kernel or input warping. Tighten length-scale bounds to prevent boundary attraction. Consider fixing x₃ at low values and doing a 2D search over x₁, x₂.

## Performance and Results

1. **Best output:** −0.034835
2. **Best input:** (0.492581, 0.611593, 0.340176) — from the initial dataset, never improved upon.
3. **Confidence in global maximum:** Low. The initial best was never beaten despite 13 queries, but the GP's systematic boundary attraction means large interior regions remain unexplored.
4. **Alignment with expectations:** Partially. The drug discovery framing correctly predicted that high x₃ causes adverse reactions. However, the smooth GP surrogate consistently failed to identify improvements.

## Ethical, Practical and General Considerations

1. **Real-world relevance:** Drug formulation optimisation, toxicology screening, combination therapy design.
2. **Synthetic limitations:** Real drug interactions involve non-linear synergies and antagonisms that a stationary GP kernel cannot capture.
3. **Scalability:** The current approach does not scale well for this function. A non-stationary kernel or Bayesian neural network surrogate would be more appropriate.
4. **Risks:** The all-time best being from the initial dataset is a warning sign — it suggests the surrogate is not learning from new queries. Future users should monitor whether new queries consistently underperform initial data, as this indicates surrogate misspecification.

# FUNCTION 4 DATASHEET

## Function Overview

1. **Function:** Function 4 — Warehouse Hyperparameter Optimisation
2. **Real-world scenario:** Optimally placing products across warehouses for a business with high online sales. An ML model approximates costly logistics calculations, and its four hyperparameters must be tuned to maximise the difference from an expensive baseline.
3. **Dimensionality:** 4D (inputs: x₁, x₂, x₃, x₄)
4. **Initial data points:** 30 (array shape: 30 × 4)
5. **Output:** Difference from expensive baseline. Initially all negative; a positive output indicates the ML model outperforms the baseline.

## Nature of the Data

1. **Initial dataset structure:** Inputs: (30, 4); Outputs: (30,). All initial outputs negative, ranging from −32.6 to −4.0.
2. **Dataset evolution:** 13 weekly queries added. The GP discovered a positive-valued region in W11 via Thompson Sampling — a breakthrough that manual and EI strategies had completely missed.
3. **Noise/randomness:** Dynamic system — outputs may vary over time as warehouse demand shifts.
4. **Function character:** Multi-modal with many local optima (as stated in the description). The positive-valued region discovered in W11 was completely isolated from all previously explored regions.

## Optimisation Strategy

1. **Methods used:** Manual weighted interpolation (W1–W4); GP/UCB (W5–W7); GP/Thompson Sampling (W8–W11); GP/EI (W12–W13).
2. **Rationale:** Thompson Sampling was introduced to escape the local optimum at (0.381, 0.425, 0.399, 0.452) = −0.120. Its stochastic nature discovered the positive-valued region at (0.418, 0.384, 0.407, 0.350) = +0.566. EI then exploited this new best.
3. **Exploration–exploitation balance:** Shifted from exploitation (EI near known best) to exploration (Thompson Sampling) to exploitation (EI of new best). The Thompson Sampling phase was the critical pivot.
4. **Strategy changes:** UCB → Thompson Sampling (W8) to escape local optimum; Thompson Sampling → EI (W12) to exploit the W11 breakthrough.

## Data Handling and Preprocessing

1. **Rescaling:** Inputs in [0,1]. `Standardize` transform applied — critical because outputs shifted from negative to positive across the capstone.
2. **Surrogate model:** BoTorch `SingleTaskGP` with Matérn-1.5 ARD kernel.
3. **Preprocessing:** ν=1.5 (jagged, multi-modal function); length-scale bounds (0.05, 0.5); noise constraint (10⁻⁵, 10⁻²) tight to prevent noise absorption.
4. **Outliers:** The W11 output (+0.566) appeared as a dramatic positive outlier against a background of negative outputs. It was retained and became the new best — confirming it was a genuine function feature, not noise.

## Weekly Iteration and Learning

1. **Landscape understanding:** Initial data suggested the best region was around (0.578, 0.429, 0.426, 0.249) = −4.026. GP-guided queries improved this to −0.120 in W5. The W11 Thompson Sampling query revealed a completely different positive-valued region.
2. **Local optima:** Confirmed. The region around (0.381, 0.425, 0.399, 0.452) = −0.120 was a local optimum — the true (or better) optimum at (0.418, 0.384, 0.407, 0.350) = +0.566 was only discovered by stochastic exploration.
3. **Most informative queries:** W5 GP query → −0.120 (first major improvement); W11 Thompson Sampling → +0.566 (breakthrough discovery of positive region).
4. **If restarting:** Use Thompson Sampling from the beginning to avoid anchoring to local optima. The dynamic system property suggests periodic re-exploration rather than progressive exploitation.

## Performance and Results

1. **Best output:** +0.56613
2. **Best input:** (0.418286, 0.384490, 0.407242, 0.350393) — achieved in Week 11 via Thompson Sampling.
3. **Confidence in global maximum:** Low-moderate. The positive region was only discovered in W11, leaving limited time to explore its neighbourhood. The true global maximum may be significantly higher.
4. **Alignment with expectations:** Partially. The many local optima warning was accurate — the function has at least two distinct performance regions (negative and positive).

## Ethical, Practical and General Considerations

1. **Real-world relevance:** Supply chain optimisation, logistics network design, inventory placement.
2. **Synthetic limitations:** Real warehouse optimisation involves discrete decisions (product categories, warehouse locations) that the continuous [0,1]⁴ input space does not capture.
3. **Scalability:** Thompson Sampling scales well to higher dimensions. For real warehouse problems with 10+ hyperparameters, TuRBO would be more appropriate.
4. **Risks:** The positive-valued region was only discovered in round 11 of 13. In a real deployment with a fixed evaluation budget, this discovery might come too late to be actionable. Earlier stochastic exploration is essential.

# FUNCTION 5 DATASHEET

## Function Overview

1. **Function:** Function 5 — Chemical Process Yield Optimisation
2. **Real-world scenario:** Optimising a four-variable chemical process in a factory to maximise yield. The function is unimodal with a single peak.
3. **Dimensionality:** 4D (inputs: x₁, x₂, x₃, x₄ representing chemical process variables)
4. **Initial data points:** 20 (array shape: 20 × 4)
5. **Output:** Chemical yield. Higher = better. Outputs range from ~64 to 8662 across the capstone.

## Nature of the Data

1. **Initial dataset structure:** Inputs: (20, 4); Outputs: (20,). Initial outputs ranged from 0.113 to 1088.86 — a factor of ~10,000×.
2. **Dataset evolution:** 13 weekly queries added. Early queries followed the gradient toward high x₂, x₃, x₄. The boundary corner (1,1,1,1) was discovered in W8 via extreme UCB exploration.
3. **Noise/randomness:** Function appears deterministic. Identical inputs returned identical outputs (confirmed: (0,1,1,1) and (1,1,1,0) both returned 4440.52; (0.98,0.98,0.99,0.99) returned 7565.50 in both W10 and W12).
4. **Function character:** Unimodal (as stated in description) with the global maximum at the boundary corner (1,1,1,1). The function increases monotonically toward this corner — confirmed by systematic boundary testing.

## Optimisation Strategy

1. **Methods used:** Manual gradient following (W1–W4); GP/UCB κ=1.5 (W5–W7); GP/UCB κ=1000 (W8 — breakthrough); GP/EI with boundary override (W9–W13).
2. **Rationale:** The unimodal property justified aggressive exploitation. The κ=1000 setting was a deliberate high-risk exploration that discovered the boundary optimum. EI with boundary override prevented duplicate queries after the corner was confirmed.
3. **Exploration–exploitation balance:** Shifted from moderate exploitation to extreme exploration (κ=1000) to pure exploitation (EI near confirmed optimum). The extreme exploration phase was the critical decision.
4. **Strategy changes:** κ=1.5 → κ=1000 (W8) to force boundary exploration; UCB → EI + override (W9) after boundary optimum confirmed.

## Data Handling and Preprocessing

1. **Rescaling:** Inputs in [0,1]. `Standardize` transform applied — essential given the 10,000× output range.
2. **Surrogate model:** BoTorch `SingleTaskGP` with Matérn-2.5 ARD kernel.
3. **Preprocessing:** ν=2.5 (smooth, unimodal function); length-scale bounds (0.1, 1.5) wide to capture the broad landscape; noise constraint (10⁻⁵, 10⁻¹).
4. **Outliers:** No outliers. The dramatic output variation (64 → 8662) reflects genuine function structure, not noise.

## Weekly Iteration and Learning

1. **Landscape understanding:** Initial data showed a clear gradient: low x₁, high x₂, x₃, x₄ → higher outputs. The boundary discovery in W8 revealed the function continues to increase all the way to (1,1,1,1).
2. **Local optima:** None — function is confirmed unimodal. The apparent plateau around 4440 (W5–W7) was not a local optimum but a region far from the true boundary maximum.
3. **Most informative queries:** W8 at (0,1,1,1) → 4440.52 (first boundary discovery); W8 at (1,1,1,1) → 8662.48 (confirmed global maximum). The κ=1000 setting that drove these queries was the most impactful single decision.
4. **If restarting:** Use κ=1000 from Module 12 to immediately explore boundary corners. The unimodal property means boundary exploration is low-risk.

## Performance and Results

1. **Best output:** 8662.4825
2. **Best input:** (1.000000, 1.000000, 1.000000, 1.000000) — achieved in Week 8.
3. **Confidence in global maximum:** High. The function is confirmed unimodal. Systematic boundary testing confirmed monotonic increase toward (1,1,1,1). Interior points consistently return lower values.
4. **Alignment with expectations:** Yes. The unimodal description was accurate. The unexpected finding was that the global maximum lies exactly at the boundary corner.

## Ethical, Practical and General Considerations

1. **Real-world relevance:** Chemical process optimisation, materials synthesis, pharmaceutical manufacturing.
2. **Synthetic limitations:** Real chemical processes have safety constraints that prevent operating at maximum input values. The boundary optimum (1,1,1,1) would likely be infeasible in practice.
3. **Scalability:** EI with boundary override scales well. For higher-dimensional chemical processes, the boundary exploration strategy remains valid — systematically testing corner points is computationally cheap.
4. **Risks:** The boundary optimum may be infeasible in real deployments. Future users should add constraint handling to prevent the acquisition function from proposing physically impossible operating conditions.

# FUNCTION 6 DATASHEET

## Function Overview

1. **Function:** Function 6 — Cake Recipe Optimisation
2. **Real-world scenario:** Optimising a five-ingredient cake recipe (flour, sugar, eggs, butter, milk) evaluated by an expert taster. Each factor contributes negative points; the goal is to minimise total penalty (maximise the negated score).
3. **Dimensionality:** 5D (inputs: x₁–x₅ representing ingredient amounts)
4. **Initial data points:** 20 (array shape: 20 × 5)
5. **Output:** Negated expert penalty score. All outputs negative — maximising means finding the recipe with the least penalty (closest to zero).

## Nature of the Data

1. **Initial dataset structure:** Inputs: (20, 5); Outputs: (20,). All outputs negative, ranging from −2.571 to −0.714.
2. **Dataset evolution:** 13 weekly queries added. Early queries used ingredient suppression (reducing x₂ and x₅). Later queries used EI and Thompson Sampling with mixed results.
3. **Noise/randomness:** Expert taster scoring introduces subjective variability. Some output variation between similar queries was observed, consistent with noisy evaluation.
4. **Function character:** Approximately additive penalty structure — each ingredient contributes independently to the total score. Low x₂ (sugar) and low x₅ (milk) consistently associated with better outcomes.

## Optimisation Strategy

1. **Methods used:** Manual ingredient suppression (W1–W4); GP/EI (W5–W7); GP/Thompson Sampling (W8–W11); GP/EI (W12–W13).
2. **Rationale:** EI was appropriate for the smooth, moderate-dimensional landscape. Thompson Sampling was introduced to add diversity after EI proposed near-identical points. Three consecutive TS regressions prompted reversion to EI.
3. **Exploration–exploitation balance:** Moderate throughout. The additive structure allowed per-ingredient reasoning — reducing x₂ and x₅ while maintaining x₁ and x₄ in the mid-to-high range.
4. **Strategy changes:** EI → Thompson Sampling (W8) for diversity; Thompson Sampling → EI (W12) after three regressions. Final EI queries produced the two best results (W7: −0.181; W13: −0.108).

## Data Handling and Preprocessing

1. **Rescaling:** Inputs in [0,1]. `Standardize` transform applied to negative outputs.
2. **Surrogate model:** BoTorch `SingleTaskGP` with Matérn-2.5 ARD kernel.
3. **Preprocessing:** ν=2.5 (smooth additive structure); length-scale bounds (0.05, 0.75); noise constraint (10⁻⁵, 10⁻¹) for noisy expert evaluation.
4. **Outliers:** No outliers removed. The worst point (−2.571, high x₂ and x₅) confirmed the ingredient suppression signal.

## Weekly Iteration and Learning

1. **Landscape understanding:** Initial data clearly showed high x₂ and x₅ in worst-performing recipes. The additive structure allowed confident directional reasoning: suppress sugar and milk, maintain flour and butter.
2. **Local optima:** Possibly present. The EI strategy converged to the (0.478, 0.319, 0.544, 0.783, 0.101) region, but Thompson Sampling's regressions suggest this may not be the global optimum.
3. **Most informative queries:** W7 at (0.478253, 0.319282, 0.543932, 0.782657, 0.101184) → −0.181 (first major improvement); W13 at (0.442035, 0.373720, 0.624334, 0.734770, 0.090751) → −0.108 (final best).
4. **If restarting:** Use an additive GP (sum of 1D GPs per ingredient) to explicitly model the separable structure. This would provide cleaner per-ingredient sensitivity estimates.

## Performance and Results

1. **Best output:** −0.10788
2. **Best input:** (0.442035, 0.373720, 0.624334, 0.734770, 0.090751) — achieved in Week 13 (final round).
3. **Confidence in global maximum:** Moderate. The final query produced the best output, suggesting the optimum may lie further in the same direction. The additive structure implies the true optimum has even lower x₂ and x₅ than currently achieved.
4. **Alignment with expectations:** Yes. The additive penalty structure was confirmed — individual ingredient effects were identifiable and actionable.

## Ethical, Practical and General Considerations

1. **Real-world relevance:** Food product formulation, cosmetics ingredient optimisation, pharmaceutical excipient selection.
2. **Synthetic limitations:** Real recipe optimisation involves discrete ingredient quantities, preparation methods, and consumer preference variation that the continuous [0,1]⁵ space does not capture.
3. **Scalability:** The additive GP approach scales well to more ingredients. For 10+ ingredient problems, ARD length-scales would identify which ingredients are most influential.
4. **Risks:** The expert taster noise means the true optimum may be obscured by evaluation variability. Future users should consider re-querying the best point multiple times to obtain a reliable estimate of the true score.

# FUNCTION 7 DATASHEET

## Function Overview

1. **Function:** Function 7 — ML Hyperparameter Tuning (6D)
2. **Real-world scenario:** Tuning six hyperparameters of an ML model (e.g., learning rate, regularisation strength, hidden layers, dropout, momentum, network width) to maximise model performance (accuracy or F1 score).
3. **Dimensionality:** 6D (inputs: x₁–x₆ representing hyperparameters)
4. **Initial data points:** 30 (array shape: 30 × 6)
5. **Output:** Model performance score (accuracy/F1). Higher = better.

## Nature of the Data

1. **Initial dataset structure:** Inputs: (30, 6); Outputs: (30,). Initial outputs ranged from 0.003 to 1.365. Point 7 (0.058, 0.492, 0.247, 0.218, 0.420, 0.731) = 1.365 was an immediate dominant outlier.
2. **Dataset evolution:** 13 weekly queries added. The low-x₁, low-x₂ signal was identified in Module 12 and consistently exploited throughout. F7 improved in 6 of 13 rounds.
3. **Noise/randomness:** ML model performance scores can be noisy due to random initialisation and data splits. Some output variation between similar queries was observed.
4. **Function character:** Smooth with a clear directional gradient — very low x₁ and x₂ consistently produce the best outputs. ARD length-scales confirmed x₁ and x₂ as the most influential dimensions.

## Optimisation Strategy

1. **Methods used:** Manual correlation analysis (W1–W4); GP/EI (W5–W13, unchanged throughout).
2. **Rationale:** EI is the standard acquisition function for hyperparameter optimisation (used in SMAC, Spearmint, Optuna). The smooth response surface and clear directional gradient made EI ideal — it naturally exploited the low-x₁, low-x₂ region without requiring manual κ tuning.
3. **Exploration–exploitation balance:** Predominantly exploitation from Module 16 onward. The clear gradient signal made exploration unnecessary — EI naturally balanced the two by querying where expected improvement was highest.
4. **Strategy changes:** None after Module 16. EI with Matérn-2.5 ARD was the correct configuration from the start and was never changed.

## Data Handling and Preprocessing

1. **Rescaling:** Inputs in [0,1]. `Standardize` transform applied.
